# タスク票 002

## タスク：縦横比が合わないときのベゼル提案と切り抜き対応

- プロジェクト：フレーム合成アプリ（FrameBezelApp）
- 起票日：2026-11-11
- 仕様の参照：~/workspace/screenshot-frame-mac/spec.md §5.3（縦横比の扱いは 2026-11-11 オーナー決定で追記済み）
- プロジェクト規約：このプロジェクトの CLAUDE.md
- 前提：チケット 001 の実装が完了していること

### 背景
チケット 001 の要確認事項3（縦横比が合わないときの余りを黒の下地にした）へのオーナー回答。単に黒で埋める前に、合うベゼルの提案と切り抜きを用意する。

### やること
1. スクショ読み込み時とベゼル変更時に、スクショの縦横比と選択中ベゼルの画面領域（aperture）の縦横比を比較する。許容差を設け、相対差がその範囲内なら「一致」として扱う（妥当な値を選び、結果欄に明記する）
2. 不一致の場合、ライブラリ内の全ベゼルから、画面領域の縦横比がスクショに合うものを探し、UI で提案する
   - 表示例：「このスクショには ◯◯ が合います」＋切り替えボタン
   - 候補が複数あれば並べて選べるようにする
3. 合うベゼルが無い場合は切り抜きで対応できるようにする
   - スクショを画面領域にフィル（はみ出して切り抜く）し、ドラッグで表示位置を調整できる。必要なら拡大縮小も
   - 切り抜き状態は書き出しにも反映される
4. 余りが出る場合の下地は黒のまま（既存実装を維持）

### 完了条件
- 上記 1〜4 が実装されている
- 結果欄に、縦横比の許容差として置いた値と、その理由が書かれている
- ビルド成功は主張しない（この環境ではビルド不可）

## 結果（実装役が記入）

- 状態：実装完了（ビルド未確認。この環境は Linux で Xcode が無いため、ビルド成功は主張しない）
- やったこと：
  1. 縦横比の比較：`AspectMatcher`（新規）で「スクショ比 ÷ 画面領域比 − 1」の絶対値（相対差）を計算。スクショ読み込み時・ベゼル変更時に `AppModel.aspectMatches` で判定
  2. 提案：不一致なら全ベゼルから許容差内のものを差の小さい順に列挙し、設定パネルに「このスクショには ◯◯ が合います」＋「◯◯ に切り替え」ボタンを表示（複数なら縦に並べて選択）
  3. 切り抜き：合うベゼルが無い場合は「切り抜きで合わせる」ボタンでフィルに切替。プレビューのドラッグで位置調整、スライダーで拡大（1〜4倍）、リセットボタン付き。`Composer.compose` に `crop: ScreenCrop` を追加し、書き出し（フル解像度）にも同じ値を反映。移動量は画面領域幅/高さで正規化しており、プレビューと書き出しで同じ見え方になる。画像が画面領域から外れて下地が見えないよう移動量は丸める
  4. 「収める」時の余りは従来どおり黒の下地（変更なし）
- **縦横比の許容差：相対差 1%（0.01）**。理由：現行 iPhone の画面比は 0.460〜0.462 に収まり、同世代内の差は 0.5% 未満。自動検出の数px誤差（約0.2%）も吸収できる。1% を超えると「収める」時の黒帯が長辺で数十px になり目立ち始めるため、それ以上は不一致として提案・切り抜きに回す。定数は `AspectMatcher.defaultTolerance`（1 か所）で調整可能
- 生成・変更したファイル：
  - 新規：Sources/FrameCore/AspectMatcher.swift
  - 変更：Sources/FrameCore/Composer.swift（`ScreenCrop` 追加、`compose` に `crop` 引数追加（既定値あり）、フィル時の描画）、Sources/App/AppModel.swift、Sources/App/ContentView.swift
- 確認したこと：コードの読み合わせのみ（座標変換：CG の y 上向きに対し crop の +y は下向きとして反転、ドラッグ量→論理座標→正規化の換算）。ビルド・実行・テストは未実施
